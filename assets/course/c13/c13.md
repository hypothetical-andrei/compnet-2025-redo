### Arhitecturi, protocoale și suprafețe de atac

* Descrie arhitectura tipică a unui sistem IoT
* Explica rolul protocolului MQTT

* Înțelege un lanț complet de atac asupra unui sistem IoT
* Explica măsuri concrete de securizare

---

### Ce este IoT (din perspectivă de rețea)

* IoT nu înseamnă doar „dispozitive”
* IoT = sisteme distribuite, conectate în rețea
* Dispozitivele sunt adesea:

  * limitate ca resurse
  * dificil de actualizat
  * expuse direct sau indirect în rețea
* Accentul cade pe:

  * protocoale
  * arhitectură
  * configurare

---

### Arhitectura tipică IoT

* Componente uzuale:

  * senzori / actuatori
  * gateway
  * broker de mesaje
  * backend / aplicații
* Comunicarea este de regulă indirectă
* Gateway-ul este punct critic de securitate

[FIG] c13-assets/fig-iot-architecture.png

---

### Modele de comunicare în IoT

* Device → Gateway
* Device → Cloud
* Device ↔ Device (mai rar)
* Comunicare:

  * sincronă
  * asincronă
  * event-driven

---

### Protocoale utilizate în IoT

* HTTP / REST
* MQTT
* CoAP (mențiune)
* Alegerea protocolului influențează:

  * latența
  * fiabilitatea
  * securitatea
  * consumul de resurse

---

### MQTT – protocol cheie pentru IoT

* Message-oriented
* Model publish / subscribe
* Broker central
* Decuplare între producători și consumatori
* Conexiuni persistente peste TCP

[FIG] c13-assets/fig-mqtt-pub-sub.png

---

### Concepte MQTT

* Broker
* Publisher
* Subscriber
* Topic-uri
* QoS (mențiune)
* Retained messages (mențiune)

---

### MQTT vs HTTP în IoT

* HTTP:

  * request / response
  * overhead mai mare
  * potrivit pentru API-uri
* MQTT:

  * asincron
  * overhead redus
  * potrivit pentru evenimente și telemetrie

[FIG] c13-assets/fig-mqtt-vs-http.png

---

### Unde apar problemele de securitate în IoT

* Autentificare absentă sau slabă
* Protocoale în clar
* Servicii expuse inutil
* Configurații implicite
* Lipsa segmentării de rețea

---

### Suprafața de atac IoT

* Nivel rețea:

  * porturi deschise
  * servicii active
* Nivel aplicație:

  * API-uri
  * brokeri de mesaje
* Nivel configurare:

  * parole implicite
  * chei expuse

[FIG] c13-assets/fig-iot-attack-surface.png

---

### Atacuri tipice asupra sistemelor IoT

* Scanare și fingerprinting
* Acces neautorizat la broker
* Control nelegitim al dispozitivelor
* Persistență pe gateway
* Mișcare laterală în rețea

---

### Lanțul unui atac (conceptual)

1. Descoperire (scanare)
2. Enumerare (servicii, versiuni)
3. Exploatare
4. Impact
5. Mitigare

### Studiu de caz: Gateway IoT vulnerabil

* Sistem tipic:

  * broker MQTT
  * server HTTP de management
  * acces SSH
* Toate rulează pe același nod
* Expus în rețea locală sau cloud

---

### De ce gateway-ul este critic

* Concentrează datele
* Are conectivitate completă
* Are de obicei privilegii ridicate
* Este țintă ideală pentru atacatori

### Măsuri de securizare IoT (sinteză)

* Segmentare de rețea
* Principiul least privilege
* Autentificare și autorizare
* Criptare (TLS)
* Monitorizare și logging

### IoT și securitate: ideea cheie

* Majoritatea vulnerabilităților IoT nu sunt hardware
* Sunt:

  * de rețea
  * de protocol
  * de configurare
* Aceleași probleme apar și în cloud
